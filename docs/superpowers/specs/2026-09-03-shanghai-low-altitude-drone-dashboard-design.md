# 上海无人机低空智慧调度大屏设计规格

**日期：** 2026-09-03  
**设计状态：** 基于 FDE 第二期工作坊实操需求、接口字段说明和 Mock 数据重新校准

## 1. 项目定位

建设“无人机低空指挥调度平台”大屏前端，用于公安、交管等场景下的无人机巡航数据展示，形成“态势一张图”的可视化能力。

系统仍以领导查看为第一优先级，同时兼顾业务和值班人员，但首期设计必须以当前已提供接口和验收标准为边界，不把尚无数据接口支撑的实时调度能力写成正式交付能力。

首期正式能力：

1. 登录与退出。
2. 顶部系统信息与用户信息。
3. 飞行总览统计。
4. 飞行案例 TOP10。
5. 飞行任务排行榜及时间范围筛选。
6. 各组织飞行统计分析。
7. 中央地图及卫星图 / 电子地图 / 暗色主题切换。
8. 1920×1080 至 7680×1440、16:9 / 21:9 / 32:9 / 48:9 自适应。

此前讨论的“无人机实时位置、动态航线、异常告警、2D/3D 切换”保留为扩展方向。当前接口没有经纬度、设备遥测、航迹点、告警或三维高度数据，因此这些能力不能与首期正式接口能力混写。

## 2. 输入资料与设计优先级

本设计以以下资料为依据：

1. `FDE实操需求文档-无人机低空智慧调度平台.md`
2. `无人机大屏接口字段说明.md`
3. `FDEaicoding无人机大屏实操接口mock数据.json`
4. `无人机大屏接口mock数据_v3.csv`

需求冲突时遵循以下优先级：

1. 明确验收标准。
2. 明确模块需求。
3. 接口真实字段。
4. Mock 数据。
5. 既有概念设计。

任何界面字段如果当前接口没有提供，不使用虚构字段补齐；需要额外接口时在扩展边界中明确标注。

## 3. 用户与信息层级

### 3.1 主要用户

领导和管理人员。

默认页面需要在 3–5 秒内回答：

- 当前飞行资源规模有多大。
- 已产生多少飞行记录、里程和时长。
- 近期有哪些典型飞行案例。
- 当前任务在各状态下如何分布。
- 哪些组织飞行最活跃。

### 3.2 次要用户

业务和值班人员。

他们主要通过时间筛选、任务状态切换、组织排行榜和地图底图切换进一步查看数据。

### 3.3 信息组织原则

首屏不做复杂业务操作，采用“看数据、切维度、看地图”的模式：

- 左侧：飞行总体情况 + 最近飞行案例。
- 中央：地图态势。
- 右侧：任务统计 + 飞行统计。
- 顶部：系统信息和用户入口。

## 4. 技术约束

### 4.1 前端技术栈

项目采用：

- Vue 3
- Vue CLI 5.x
- Sass + sass-loader
- ECharts 用于统计图表
- 地图通过独立 Map Adapter 接入

需求允许 Vue 2.6.14 或 Vue 3；新项目优先采用 Vue 3，避免从零项目继续使用 Vue 2。

### 4.2 浏览器兼容

至少覆盖：

- Chrome
- Edge
- Firefox
- Safari
- 国产浏览器极速模式

不得依赖仅 Chromium 可用的非标准 API 实现核心功能。

### 4.3 大屏分辨率

支持：

- 16:9
- 21:9
- 32:9
- 48:9
- 1920×1080 至 7680×1440

不能简单按 1920×1080 整页等比缩放后强行拉伸到超宽屏。页面采用响应式 Grid 布局，地图区域吸收新增宽度，左右业务栏保持合理阅读宽度。

## 5. 页面结构

系统包含两个主要页面：

1. 登录页 `/login`
2. 大屏主页 `/dashboard`

### 5.1 大屏总体布局

```text
┌──────────────────────── 顶部导航栏 ────────────────────────┐
│ 时间/日期/天气     无人机低空指挥调度平台       用户/首页/头像 │
├──────────────┬──────────────────────────┬───────────────┤
│              │                          │               │
│ 飞行总览     │                          │ 飞行任务排行榜 │
│              │        中央地图          │               │
│ 飞行案例TOP10│                          │ 飞行统计分析   │
│              │                          │               │
└──────────────┴──────────────────────────┴───────────────┘
```

中央地图始终是最大视觉区域。

16:9 下建议三栏比例约为 `24% / 52% / 24%`；随着屏幕变宽，优先增加中央地图宽度，不同比例屏幕不改变左、右信息顺序。

## 6. 登录页面

页面标题固定为“无人机低空指挥调度平台”。

包含：

- 用户名
- 密码
- 验证码
- 登录按钮

行为：

1. 登录成功进入 `/dashboard`。
2. 登录失败在表单区域给出明确错误。
3. 大屏点击退出后清除本地登录态并返回 `/login`。
4. 当前资料没有提供真实登录接口，因此首期使用前端 Mock 登录，不伪造后端鉴权能力。

视觉上保持与大屏一致的深色城市指挥风格，但登录页不堆叠大屏图表元素。

## 7. 顶部导航栏

顶部只承担系统级信息，不承担业务统计。

### 7.1 左侧

显示：

- 实时时间
- 星期
- 日期
- 天气

天气数据源当前资料未提供。首期可以使用固定 Mock 数据，并在代码中独立为 `weatherService`，避免与业务接口混杂。

### 7.2 中部

系统标题：

“无人机低空指挥调度平台”

### 7.3 右侧

显示：

- 用户名
- 首页按钮
- 用户头像
- 退出入口

不在顶部重复放置大量飞行 KPI，避免与左侧“飞行总览”重复。

## 8. 左侧：飞行总览

数据源：

`GET /openTotalDataByDept`

接口字段：

- `shelterNum`：方舱数量
- `flyLineNum`：飞行航线数量
- `achieveNum`：成果数量
- `flyerNum`：飞手数量
- `workOrderNum`：工单数量
- `recordCount`：飞行架次
- `flyPlaneNum`：飞行计划数量
- `flightLength`：飞行里程
- `durationHours`：飞行时长

### 8.1 信息层级

不把 9 个值做成 9 张等权 KPI 卡片。

建议分为两级：

一级核心统计：

- 飞行架次
- 飞行里程
- 飞行时长
- 飞行计划

二级资源统计：

- 方舱
- 飞手
- 航线
- 工单
- 成果

这样领导先看到实际飞行规模，再看到资源基础。

### 8.2 数据格式

- 飞行里程显示单位 `km`
- 飞行时长显示单位 `h`
- 数量类使用整数
- 接口返回字符串的里程、时长仅在展示层格式化，不修改原始 DTO

## 9. 左侧：飞行案例 TOP10

数据源：

`GET /openAssociatedFlyRecord`

接口支持：

- `pageNum`
- `pageSize`
- `flyRecordId`
- `flyLineName`
- `shelterId`

首屏调用：

- `pageNum = 1`
- `pageSize = 10`

前端按 `createTime` 降序展示，保证满足 TOP10 验收语义。

### 9.1 卡片字段映射

| 页面字段 | 接口字段 | 说明 |
|---|---|---|
| 序号 | 前端生成 | 1–10 |
| 飞行编号 | `flyRecordId` | 使用记录主键作为展示编号 |
| 飞行航线 | `flyLineName` | 如“指点飞行”“航线飞行” |
| 飞行记录名称 | `flyRecordName` | 原样展示 |
| 执行时间 | `createTime` | 格式化为 `MM-dd HH:mm` |
| 方舱 | `shelterName` | 当前接口明确提供 |
| 飞手 | `flyerName` | 作为次级信息 |

需求文档中写有“执行设备”，但当前接口没有 `deviceId/deviceName`。因此设计不把 `shelterName` 擅自定义为执行设备；首期字段名称使用“方舱”。若后续补充设备字段，再调整为“执行设备”。

### 9.2 视觉表现

采用纵向紧凑卡片，不使用普通后台表格。

每张卡片突出：

- 飞行记录名称
- 航线类型
- 执行时间

编号、飞手、方舱使用较弱层级。

## 10. 中央地图

中央地图是页面视觉中心。

### 10.1 首期正式能力

必须支持三种底图：

- 卫星图
- 电子地图
- 暗色主题

地图中心规则：

1. 如果已有设备位置数据，中心定位设备所在地。
2. 当前接口没有设备坐标，因此首期默认中心为上海。
3. 后续设备坐标接口接入后再启用自动定位。

### 10.2 地图控件

地图左上或右上采用轻量悬浮控制：

- 卫星
- 电子
- 暗色

避免用大型按钮遮挡地图。

### 10.3 地图技术边界

地图业务组件不直接依赖具体供应商 SDK。

定义统一适配能力：

```ts
interface MapAdapter {
  mount(container: HTMLElement): void
  setBaseLayer(type: 'satellite' | 'vector' | 'dark'): void
  setCenter(lng: number, lat: number, zoom?: number): void
  resize(): void
  destroy(): void
}
```

首期只实现验收所需底图与视口能力。

### 10.4 实时位置 / 航线扩展

此前提出的实时无人机位置、动态航线可以保留在视觉原型中，但必须与真实业务数据层分开：

- 当前没有经纬度接口，不把飞行记录伪装成实时无人机位置。
- 当前没有航迹点列表，不从 `flyLineName` 推导航线坐标。
- 如演示必须出现无人机图标或航线，使用独立 `mapDemoOverlay` Mock 数据，并明确属于演示层。
- 后续获得真实设备和航迹接口后，才能转为正式数据层。

3D 地图同样作为扩展能力，不纳入当前验收基线。

## 11. 右侧：飞行任务排行榜

数据源：

`POST /openTaskOverview`

任务状态严格使用接口定义：

- 待派发 `dispatchedNum`
- 派发中 `dispatchingNum`
- 已接单 `receivedNum`
- 已结单 `completedNum`

不再使用“待执行 / 执行中 / 已完成 / 异常”等当前接口不存在的状态。

### 11.1 时间筛选

支持：

- 今日
- 本周
- 本月
- 本年
- 累计

统一转换为：

```ts
{
  loginUserId,
  loginDeptId,
  startTime,
  endTime
}
```

时间规则：

- 今日：当天 00:00 至当前日期结束
- 本周：本周第一天至今天
- 本月：当月 1 日至今天
- 本年：当年 1 月 1 日至今天
- 累计：2024-01-01 至今天

### 11.2 状态切换

顶部显示四个状态值。

点击任一状态后，下方组织排行榜从 `taskOverviewRespVoList` 读取各组织对应数量和接口返回百分比。

页面不自行计算不存在的任务完成率口径。

### 11.3 展示方式

采用：

- 四状态数字切换条
- 组织横向排名条形图
- 当前选中状态高亮

不采用复杂饼图叠加，以便超宽屏和领导远距离查看。

## 12. 右侧：飞行统计分析

数据源：

`POST /openNewTotalDataByDay`

主要字段：

- `recordCount`：飞行架次
- `flightLength`：飞行里程（km）
- `durationHours`：飞行时长（h）
- `countViewRespVos`：下级组织统计
- `secondCountViewRespList`：按日期统计

### 12.1 默认范围

默认查询：

`2024-01-01` 至今天。

### 12.2 展示设计

模块顶部提供指标切换：

- 飞行架次
- 飞行里程
- 飞行时长

主体展示各组织横向排行榜。

底部可使用一条小型趋势线展示 `secondCountViewRespList`，但趋势只能使用接口真实返回的按日期统计数据；无数据时不补造连续日期。

## 13. 工单统计接口处理

现有资料还提供：

`POST /openWorkOrderOverview`

可获得：

- 工单总量
- 待接收
- 已接收
- 已完结
- 下级组织统计
- 按日期统计

但正式“需要实现的模块”和验收标准没有要求独立工单图表。

因此首期：

- 不新增工单排行榜模块。
- `workOrderNum` 只在飞行总览中作为资源统计展示。
- `openWorkOrderOverview` 保留 service 和数据模型扩展位置，暂不占用首屏区域。

## 14. AI 识别能力边界

项目背景提到 AI 自动识别交通事故、车辆、行人、烟雾等目标。

当前提供的 `openAssociatedFlyRecord` 虽然接口说明标题为“分页查询AI识别结果”，但返回字段只有飞行记录、航线、飞手、时间和方舱，没有：

- 识别目标类型
- 识别数量
- 置信度
- 识别图片
- 事故类型
- 经纬度

因此首期不能设计“AI 事件实时列表”“识别目标统计”“事故告警地图”等依赖这些字段的正式模块。

若后续提供 AI 识别结果字段，可在中央地图与飞行案例之间新增联动，而无需改变现有统计模块。

## 15. 数据层设计

### 15.1 API Service

业务组件不得直接读取 JSON / CSV Mock 文件。

划分：

```text
src/services/
├── authService.ts
├── flightOverviewService.ts
├── flightRecordService.ts
├── taskOverviewService.ts
├── flightStatisticsService.ts
├── workOrderService.ts
└── weatherService.ts
```

### 15.2 DTO 与 ViewModel 分离

接口返回结构按字段说明定义 DTO。

页面需要的格式化、排序、TOP10 截取、时间区间转换在 mapper / composable 中完成，不修改原始 DTO。

例如：

```ts
type FlightOverviewDto = {
  shelterNum: number
  flyLineNum: number
  achieveNum: number
  flyerNum: number
  workOrderNum: number
  recordCount: number
  flyPlaneNum: number
  flightLength: string
  durationHours: string
}
```

### 15.3 请求失败

每个业务模块独立处理 loading / success / empty / error。

单个接口失败不得导致整个大屏白屏。

## 16. 视觉设计

整体定位为“城市低空指挥态势大屏”，但不使用常见的重霓虹、重描边、满屏发光设计。

### 16.1 色彩

- 主背景：深蓝黑
- 主信息：低饱和蓝 / 青蓝
- 强调：少量亮青
- 警示：仅在错误或异常状态使用橙 / 红
- 文字：高对比白灰分级

当前接口没有告警业务数据，因此红色不承担常驻“告警中心”的视觉角色。

### 16.2 组件

- 大数字只用于核心统计。
- 飞行案例使用紧凑卡片。
- 排行榜以横条和数字为主。
- 图表网格线、坐标轴降低存在感。
- 地图保持最大面积和最高视觉层级。

### 16.3 动效

只保留：

- 数字加载过渡
- 排行条宽度过渡
- 卡片进入淡入
- 地图底图切换渐变
- 数据刷新轻提示

不使用持续闪烁、呼吸边框和无业务含义的粒子动画。

## 17. 超宽屏适配策略

### 17.1 布局

使用 CSS Grid + `clamp()` 控制侧栏宽度：

- 16:9：完整三栏
- 21:9：地图优先增宽
- 32:9：地图继续增宽，左右栏适当增加内部留白
- 48:9：不复制左右模块，不把一套 16:9 页面横向拉伸

### 17.2 高度

垂直方向按照固定信息层级布局，避免因超宽屏而降低字号。

### 17.3 Resize

窗口尺寸变化时：

- 地图执行 `resize()`
- ECharts 执行 `resize()`
- 不重新请求业务接口

## 18. 状态与异常

统一模块状态：

- loading
- success
- empty
- error

### 18.1 空数据

显示“暂无数据”，不展示 0 值排行榜伪装成真实统计。

### 18.2 接口失败

模块保留标题和结构，显示局部错误信息，并提供重新加载入口。

### 18.3 地图失败

左右统计模块仍可正常查看；地图区域单独显示加载异常。

## 19. 验收映射

| 验收项 | 设计实现 |
|---|---|
| 左/中/右三栏 + 顶部导航 | 第 5、7–12 节 |
| 飞行总览数据正确展示 | 第 8 节，`openTotalDataByDept` |
| 飞行案例 TOP10 按时间降序、卡片展示 | 第 9 节，`openAssociatedFlyRecord` |
| 任务排行榜支持今日/本周/本月/本年/累计 | 第 11 节 |
| 状态切换展示各组织占比 | 第 11 节，`taskOverviewRespVoList` |
| 飞行统计展示各组织架次/里程/时长 | 第 12 节 |
| 地图卫星/电子/暗色切换 | 第 10 节 |
| 多比例、多分辨率无拉伸无裁切 | 第 17 节 |
| 登录成功进入大屏、退出返回登录 | 第 6 节 |

## 20. 首期明确不实现

除非获得新增接口或明确新增验收要求，以下内容不进入首期正式实现：

- 真实无人机实时经纬度
- 飞行高度、速度、电量、信号等遥测
- 动态真实航迹
- 偏航 / 失联 / 低电量等告警
- 禁飞区侵入判断
- 任务详情和单任务执行进度
- AI 识别目标分类与置信度
- 3D 城市地图
- 工单独立排行榜
- 任务创建、审批和调度操作
- 权限管理后台

这些内容可以作为后续版本扩展，不在当前页面通过虚构数据与正式接口混合实现。

## 21. 成功标准

首期版本完成后应满足：

1. 页面结构与 FDE 实操需求一致。
2. 五个已给接口均有明确的数据层归属，页面只消费当前模块真正需要的数据。
3. 所有正式展示字段都能追溯到接口字段或明确的前端计算规则。
4. 任务状态、TOP10、时间范围与接口语义一致。
5. 地图满足卫星 / 电子 / 暗色切换和上海默认中心。
6. 16:9 至 48:9 均保持结构完整、文字可读、地图不被压缩成次要区域。
7. 后续增加真实无人机位置、航迹、AI 识别结果时，不需要推翻现有统计模块和整体布局。
