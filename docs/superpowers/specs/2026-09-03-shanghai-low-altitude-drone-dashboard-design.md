# 上海无人机低空智慧调度大屏设计规格

**日期：** 2026-09-03

## 1. 项目目标

建设一套面向上海低空无人机运行管理的智慧调度大屏前端。系统以领导查看为第一优先级，同时兼顾调度、值班和业务人员使用。

当前阶段定位为“可落地前端”：界面、数据结构、交互逻辑和状态联动按正式生产系统方式设计，但数据先使用模拟实时数据，后续可以替换为真实无人机遥测、任务、航线、告警和 GIS 服务接口。

首期核心能力限定为：

1. 展示无人机实时位置。
2. 展示无人机当前/规划航线。
3. 展示任务状态和执行进度。
4. 展示关键异常告警，并与地图、航线、任务进行联动。
5. 支持上海全市总览与重点区域下钻。
6. 支持 2D / 3D 地图双模式。

不在首期范围内：任务创建、任务审批、复杂调度编排、完整告警处置闭环、设备管理后台和权限管理后台。

## 2. 用户与使用场景

### 2.1 主要用户

主要用户为领导和管理人员，需要在较短时间内判断上海全市低空运行是否正常、当前任务规模、关键区域状态以及是否存在异常事件。

### 2.2 次要用户

次要用户包括调度人员和值班人员，需要进一步查看具体无人机、任务、航线以及异常位置。

### 2.3 信息层级原则

大屏采用“两层信息结构”：

- 第一层为全局态势，适合领导快速浏览。
- 第二层为地图下钻和对象详情，适合调度和值班人员进一步定位问题。

默认界面不得要求用户先进行复杂筛选才能理解全局状态。

## 3. 核心布局

采用“中央地图主视觉 + 顶部关键指标 + 左右业务侧栏 + 底部趋势/动态信息”的大屏布局。

### 3.1 顶部

顶部由系统标题和综合运行指标组成。

核心指标固定为：

- 在线无人机
- 执行中任务
- 今日飞行架次
- 任务完成率
- 当前告警
- 重点区域运行状态

指标优先展示当前值。同比、环比、昨日值只作为次级信息，不抢占主要视觉层级。

### 3.2 中央地图

中央地图占据页面最大面积，是整个系统的核心交互区域。

默认进入上海全市 3D 态势视图。用户可以切换：

- 3D 地图
- 2D 地图
- 全市总览
- 重点区域

地图承载无人机、航线、重点区域、禁飞/限制区域和异常事件位置。

### 3.3 左侧区域

左侧聚焦“任务”。建议包含：

- 任务总览
- 待执行任务数
- 执行中任务数
- 已完成任务数
- 异常任务数
- 重点任务列表

列表中的任务与地图对象双向联动。

### 3.4 右侧区域

右侧聚焦“运行风险和对象详情”。建议包含：

- 告警中心
- 航线监控
- 当前选中无人机详情

默认显示告警与航线状态；用户选中无人机后，详情区切换到该无人机运行信息。

### 3.5 底部区域

底部用于展示不需要抢占主视觉、但适合观察变化趋势的信息：

- 今日飞行趋势
- 区域活跃度
- 全市事件动态

底部不放置需要用户频繁操作的主要控制项。

## 4. 地图与低空态势设计

### 4.1 上海全市总览

默认展示上海市行政区域和主要重点低空运行区域。重点区域至少在数据模型层支持：浦东新区、临港新片区、虹桥区域以及后续可配置区域。

全市视图主要回答：

- 无人机主要分布在哪里。
- 哪些区域当前飞行活动最密集。
- 哪些区域存在异常。
- 当前主要任务航线如何分布。

### 4.2 重点区域下钻

点击重点区域后进入局部视图，并保留全局返回入口。

区域下钻后增加信息密度，包括：

- 具体无人机位置
- 航线节点
- 起降点
- 飞行高度
- 局部告警
- 当前执行任务

### 4.3 2D / 3D 模式

3D 模式用于领导总览和空间态势展示，突出低空飞行层次和城市空间关系。

2D 模式用于精细调度，强调位置、航线、边界、告警范围和标签可读性。

切换模式时保持：

- 当前选中无人机
- 当前区域
- 当前筛选条件
- 当前航线

不得因模式切换重置业务上下文。

## 5. 无人机实时位置

### 5.1 地图表达

每架在线无人机在地图上对应一个可交互对象。

状态至少包括：

- 正常飞行
- 待命/悬停
- 低电量
- 偏航
- 失联
- 异常

默认只显示对态势判断必要的信息，避免所有无人机同时展开文本标签造成地图拥挤。

### 5.2 对象选择

点击无人机后：

1. 地图高亮该无人机。
2. 高亮其当前任务航线。
3. 右侧显示无人机详情。
4. 左侧任务列表定位对应任务。

无人机详情至少包含：

- 无人机 ID
- 型号
- 当前任务
- 当前区域
- 经度/纬度
- 高度
- 地速
- 航向
- 电量
- 信号状态
- 飞行状态
- 最近数据更新时间

## 6. 航线设计

### 6.1 航线状态

航线至少支持：

- 正常
- 关注
- 异常

航线与任务和无人机保持明确关联。

### 6.2 地图表达

正常航线使用低干扰的连续轨迹表达；当前选中航线增强亮度和层级；异常航段单独高亮。

航线上可以包含：

- 起点
- 终点
- 关键航点
- 当前飞行位置
- 已飞航段
- 未飞航段

### 6.3 航线异常

首期考虑以下异常：

- 偏离规划航线
- 高度超限
- 进入限制区域
- 航线冲突提示

当航线异常时，应同时作用于地图、告警中心和关联任务。

## 7. 任务状态

任务状态采用：

- 待执行
- 执行中
- 已完成
- 异常

任务数据至少包含：

- 任务 ID
- 任务名称
- 任务类型
- 执行区域
- 关联无人机
- 关联航线
- 起点
- 终点
- 开始时间
- 计划结束时间
- 实际进度
- 当前状态

任务列表优先展示“执行中”和“异常”。

点击任务时，地图自动定位相关区域并突出对应无人机和航线。

## 8. 告警中心

告警属于核心能力，但大屏首期只负责监控和定位，不承担完整处置工作流。

首期告警类型包括：

- 偏航
- 失联
- 低电量
- 任务超时
- 禁飞/限制区域侵入

告警至少分为：

- 严重
- 重要
- 一般

### 8.1 告警联动

用户点击告警后：

1. 地图定位对应无人机或区域。
2. 无人机对象进入高亮状态。
3. 异常航段进入高亮状态。
4. 关联任务进入选中状态。
5. 右侧展示告警相关对象详情。

严重告警产生时可以提供短时视觉强调，但不得持续大面积闪烁影响领导查看。

## 9. 关键交互

系统核心交互限定为：

- 2D / 3D 切换
- 全市 / 重点区域切换
- 点击区域下钻
- 点击无人机查看详情
- 点击任务定位地图
- 点击告警定位异常
- 点击航线查看状态
- 基础状态筛选

首期不增加复杂表单和后台式操作。

## 10. 数据与前端架构

### 10.1 数据源抽象

前端所有业务数据通过统一 service 层获取，禁止页面组件直接依赖模拟数据文件。

建议划分为：

- `aircraftService`：无人机实时状态
- `missionService`：任务状态
- `routeService`：航线与航点
- `alertService`：告警
- `regionService`：区域与地图配置

当前实现由 mock adapter 提供数据；未来接入正式接口时替换 adapter，不修改主要视图组件。

### 10.2 实时数据模型

模拟阶段使用定时数据流模拟位置和状态变化。前端业务层接口设计应兼容未来 WebSocket 或 MQTT 网关推送。

建议统一事件类型：

- `aircraft.position.updated`
- `aircraft.status.changed`
- `mission.status.changed`
- `mission.progress.updated`
- `route.status.changed`
- `alert.created`
- `alert.updated`

### 10.3 状态管理

全局只保存需要跨区域联动的状态：

- 当前地图模式
- 当前区域
- 当前选中无人机
- 当前选中任务
- 当前选中告警
- 当前筛选条件
- 实时业务实体状态

纯 UI 展开/收起状态保留在组件内部。

## 11. 地图技术方案

前端地图层需要抽象为独立模块，以避免业务组件绑定特定地图 SDK。

地图适配层至少暴露：

- 设置 2D / 3D 模式
- 设置视口
- 定位区域
- 添加/更新无人机
- 添加/更新航线
- 高亮对象
- 显示告警区域
- 清理业务图层

首期可以基于支持 2D/3D 的 Web GIS/三维地图技术实现，但技术选型必须保证后续替换真实上海 GIS 数据时不需要重写业务状态层。

## 12. 视觉设计原则

视觉风格定位为“城市低空运行指挥平台”，而非普通互联网后台。

原则：

- 深色背景可作为默认大屏环境，但避免泛滥的霓虹蓝和无意义发光边框。
- 地图是视觉中心，侧栏不得压缩地图到次要区域。
- 正常状态使用克制的冷色信息表达。
- 告警只使用有限的黄色、橙色、红色层级。
- 数字指标强调可读性，不使用过度装饰字体。
- 领导在 3-5 秒内能够识别：当前运行规模、是否异常、异常在哪里。

## 13. 异常与降级

### 13.1 实时数据中断

若实时数据流中断：

- 保留最后一次有效数据。
- 明确显示数据更新时间。
- 显示“数据连接异常”状态。
- 不将历史位置继续模拟为实时位置。

### 13.2 地图加载失败

地图失败不应导致整个大屏白屏。指标、任务和告警仍需可用，并显示地图加载异常状态。

### 13.3 单模块数据失败

无人机、任务、航线、告警模块分别处理错误，避免一个服务异常导致所有业务数据不可用。

## 14. 性能目标

首期前端设计以可扩展为目标，地图更新不得通过全页面重新渲染实现。

设计目标：

- 支持至少数百架无人机对象持续位置更新。
- 位置变化仅更新地图对象属性。
- 任务和告警列表采用稳定 key 和增量更新。
- 地图航线数据与统计图表数据解耦。
- 动画只用于帮助理解状态变化，不作为持续装饰。

## 15. 测试重点

首期测试围绕业务联动和状态正确性，不增加与实际价值无关的测试层级。

至少验证：

1. 模拟实时位置能够持续更新。
2. 点击无人机后地图、任务和详情正确联动。
3. 点击任务后正确定位无人机和航线。
4. 告警产生后对应无人机、航线和任务正确高亮。
5. 2D / 3D 切换不丢失当前选中状态。
6. 全市/重点区域切换保持业务数据一致。
7. 数据服务异常时对应模块正确降级。

## 16. 首期交付结果

首期最终应形成一个可运行的正式前端原型，具备完整的大屏信息架构和实际交互，而不是静态展示稿。

演示过程应能够连续完成：

1. 进入上海全市低空态势。
2. 观察无人机实时移动和航线。
3. 查看执行中任务。
4. 下钻浦东等重点区域。
5. 选择一架无人机查看详情。
6. 触发或模拟一个偏航/低电量等告警。
7. 告警自动关联地图位置、航线和任务。
8. 在 2D / 3D 模式之间切换并保持当前业务上下文。

该流程作为首期产品是否达到设计目标的主要验收依据。
